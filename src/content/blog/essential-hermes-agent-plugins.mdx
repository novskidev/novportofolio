# 11 Essential Hermes Agent Plugins for a Lean VPS Setup

In my previous post, [Hermes Agent vs OpenClaw](/blog/why-i-prefer-hermes-agent/), I wrote about why Hermes Agent became my primary assistant on a low-resource VPS. Out of the box, Hermes provides a solid baseline: lightweight RAM usage, terminal access, and a native Telegram gateway.

However, once you move from casual prompt-response interactions to delegating continuous background jobs, the default agent architecture hits practical bottlenecks:

1. **Context window bloat:** Dumping dozens of tool schemas and system instructions into every turn drains budget and exhausts token limits.
2. **Context amnesia:** Ephemeral session buffers lose context across weekly operational cycles.
3. **Dirty runtime environments:** Ad-hoc scripts produce messy file artifacts that clutter the server filesystem.
4. **Silent failures:** Background cron tasks can fail silently without anyone noticing unless an alert is pushed.

To solve this, I run a curated stack of 11 plugins divided across four architectural layers. Here is how each plugin works and why it earns its place in my daily configuration.

---

## Pillar 1: Context and Engine Efficiency

Running an agent on a small VPS means every token and CPU cycle counts. These four plugins prevent token waste and keep prompt size under tight control.

### 1. `rtk-rewrite` (Token Reduction & CLI Interceptor)

Standard CLI tools emit verbose banners, ASCII tables, and trailing empty lines that burn tokens without adding useful context.

`rtk-rewrite` acts as an interceptor between Hermes and the underlying Linux shell. When the agent runs common terminal utilities (`git status`, `docker ps`, `ls -la`, `curl`), the plugin filters the raw stdout through rule-based compactors before returning it to the context window. Cleaned git diffs and structured command output save hundreds of tokens per tool call.

### 2. `skill-retrieval` (Dynamic BM25 Skill Routing)

Hermes allows defining modular skills, but loading every skill prompt into the system instructions at startup creates massive overhead.

`skill-retrieval` indexes all available skills locally using a BM25 sparse retrieval engine. Instead of stuffing every instruction into the prompt upfront, Hermes checks the user's intent, queries the BM25 index, and injects only the single relevant skill procedure into the active prompt. If I ask about server maintenance, the content drafting skill never touches memory.

### 3. `toolrush` (On-Demand Tool Orchestration)

Similar to skills, exposing 40 different MCP tools simultaneously degrades model reasoning and increases latency.

`toolrush` manages tools on demand. It presents Hermes with a minimal meta-tool registry. When the agent determines a task requires a specific external capability, `toolrush` mounts that tool definition dynamically for the duration of the task and unloads it once execution finishes.

### 4. `antigravity-subscription-directsdk` (DirectSDK Provider)

Running an agent through generic third-party proxy wrappers adds unpredictable latency and intermittent timeouts.

`antigravity-subscription-directsdk` connects Hermes directly to the upstream model provider via native API bindings. It bypasses intermediaries, ensures direct streaming responses, and handles connection retries reliably during long-running background tasks.

---

## Pillar 2: State and Long-Term Persistence

An operational assistant is only useful if it retains context across sessions without manual prompt reminders.

### 5. `mnemosyne` (Persistent Semantic Memory)

Standard vector search setups often retrieve irrelevant fragments because they lack semantic boundaries.

`mnemosyne` handles persistent memory storage using embeddings stored in a lightweight local vector index. When I mention personal preferences, server IPs, deployment scripts, or recurring task parameters, `mnemosyne` stores and extracts relevant historical facts automatically. The agent remembers my past preferences without needing manual reminders in every prompt.

### 6. `tameru` (State & Asset Storage)

AI agents frequently generate intermediate artifacts: JSON reports, generated charts, temporary download packages, and diff snapshots.

`tameru` acts as a structured scratchpad and asset vault. Rather than scattering random temporary files across `/tmp` or the user home directory, `tameru` indexes each artifact with TTL expiration, metadata tags, and retrieval keys. When Hermes needs to review an output from three days ago, it queries `tameru` cleanly.

---

## Pillar 3: Web Intelligence and Ingestion

A terminal agent frequently needs to pull reference documentation, verify breaking news, and extract content from URLs.

### 7. `crawl4ai-extract` (Deep Web Scraping & Crawling)

Simple HTTP fetches fail on JavaScript-heavy documentation sites or single-page applications.

`crawl4ai-extract` runs an optimized headless crawler specifically tuned for LLM consumption. It bypasses client-side rendering traps, handles pagination, and outputs structured DOM snapshots without crashing low-memory VPS instances.

### 8. `web-defuddle` (Article Markdown Extractor)

Sending full HTML pages directly into an LLM context is wasteful and introduces noise from cookie banners, navigation menus, and tracking scripts.

`web-defuddle` strips boilerplate from arbitrary blog posts and news articles, converting the core text into clean, readability-grade Markdown. It isolates the article body, normalizes code snippets, and strips unnecessary tags, reducing prompt consumption by up to 80% per URL.

---

## Pillar 4: Coordination and Real-World Ops

The final layer moves Hermes from an on-demand terminal assistant into an active operational supervisor.

### 9. `omh` (Oh-My-Hermes Multi-Agent Framework)

Complex workflows, such as auditing a repository or drafting multi-stage release notes, fail when a single agent tries to plan, execute, and review simultaneously.

`omh` (Oh-My-Hermes) introduces a lightweight multi-agent orchestration pattern inside Hermes. It lets a primary orchestrator dispatch discrete sub-tasks to specialized sub-agents with constrained context windows, synthesizing their outputs before delivering the final answer to Telegram.

### 10. `cron-status-alert` (Scheduled Task Monitoring & Discord Alerts)

Hermes excels at scheduled cron jobs like automated backups, database snapshots, and uptime checks. However, if a cron job silently fails in the middle of the night, checking terminal logs manually defeats the purpose of automation.

`cron-status-alert` wraps all scheduled jobs with health checks. On job success, it quietly logs execution metrics. On non-zero exit codes or uncaught exceptions, it immediately dispatches an incident payload to my private Discord alerts channel with the error trace attached.

### 11. `homeassistant` (Home IoT Automation)

Having an agent that can only talk to servers is half the picture.

The `homeassistant` plugin links Hermes directly to my self-hosted Home Assistant instance via local REST and WebSocket APIs. Through Telegram, I can check room temperatures, trigger workspace lighting scenes, or ask the agent to toggle smart plugs when builds finish, all without exposing the home network to public cloud brokers.

## Final Thoughts

The key to running an autonomous agent on modest hardware is not using a larger model or adding more CPU cores. It comes down to context hygiene and intentional tool design.

By keeping the context window clean with `rtk-rewrite` and `skill-retrieval`, persisting state with `mnemosyne` and `tameru`, and connecting background tasks to Discord and Home Assistant, Hermes Agent functions as a dependable, low-maintenance operations partner.
